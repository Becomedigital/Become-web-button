# Web Integration

URL-based integration for WhatsApp, email, or direct links. The user receives a link and completes verification in a full-page flow hosted at `https://websdk.svi.becomedigital.net/`.

Before you build a link, have your contract ID and an access token generated by your backend. See [Prerequisites](integration-guide.md#prerequisites).

## Link Format

```
https://websdk.svi.becomedigital.net/?contractId=contract_123&accessToken=eyJ...&flow=onboarding&locale=es
```

## Parameters

All parameters are passed as URL query parameters. URL-encode every value, `redirectUrl` in particular.

### Required

| Parameter | Description |
|-----------|-------------|
| `contractId` | Contract identifier |
| `accessToken` | JWT access token, generated by your backend. See [Generate the access token](integration-guide.md#generate-the-access-token) |

### Common optional parameters

| Parameter | Description | Values |
|-----------|-------------|--------|
| `userId` | User identifier | Optional in onboarding, required in reverification |
| `flow` | Flow type | `onboarding` (default, verification), `reverification` |
| `locale` | Language locale | `es` (default). See [Texts and locales](customization.md#texts-and-locales) |
| `country` | ISO 3166 country code | Skips country selection |
| `docType` | Document type | `national-id`, `passport`, `driving-license` |
| `redirectUrl` | Page the browser opens when the verification ends | See [Behavior](#behavior) |
| `webhookUrl` | Temporary alternative to the webhook configured on the backend | Not recommended. See [Webhook notification](integration-guide.md#webhook-notification) |
| `themeMode` | Which palette is active | `light` (used when omitted), `dark`, `system`. See [Theme mode](customization.md#theme-mode) |
| `externaltxid` | External transaction ID | For tracing |

Every parameter, and the kebab-case names also accepted (`contract-id`, `theme-mode`, and so on), is listed in the [API reference](api.md#hosted-page-url).

## Build the link

Build the link on your backend, after you request the access token, so the token and every value are URL-encoded:

```javascript
// Your backend
const link = new URL('https://websdk.svi.becomedigital.net/');
link.search = new URLSearchParams({
  contractId,
  accessToken,
  userId,
  flow: 'onboarding',
  locale: 'es',
  redirectUrl: 'https://myapp.com/thank-you',
}).toString();
```

The link carries the access token. Send it only to the person who verifies. For a complete WhatsApp walkthrough, including a `redirectUrl` that returns the person to the chat, see [Example: WhatsApp flow](integration-guide.md#example-whatsapp-flow). The same approach applies to email and other channels.

## Behavior

- The hosted page reads the query parameters and runs the verification flow in fullscreen. The card stays within the browser window.
- The `mode` parameter is **forced to `fullscreen`** regardless of what is passed.
- If startup fails, the page shows a message for the `locale` you passed. A retry control appears only when the failure can be retried. The page does not show the access token. Leaving the flow and a completed verification are not startup failures. Your application is not notified of that failure in the browser.
- When the API accepts the verification and `redirectUrl` is set, the hosted page navigates the browser to that URL. If the page is still open when the person closes the result screen, it navigates to `redirectUrl` again.
- When the person closes the final error screen, the browser also navigates to `redirectUrl`. A startup failure or the person leaving the flow does not navigate there. Arriving at `redirectUrl` does not mean the verification succeeded.
- The person goes through the same verification flow as in the web component.
- Visual language, colors, and density come from the contract's public configuration in the Dashboard, the same options as the web component. They are not URL parameters. See [customization.md](customization.md).

## After the verification

The hosted page's responsibility ends when the person leaves the flow. It does not give your application the result.

1. **Webhook notification.** Your server is notified that the transaction is completed and its results are ready. The webhook is configured on the backend for your contract. It does not carry transaction data. See [Webhook notification](integration-guide.md#webhook-notification).
2. **Result retrieval.** Your system requests the transaction results with the API. See [Retrieve the transaction results](integration-guide.md#retrieve-the-transaction-results).

## Example

```
https://websdk.svi.becomedigital.net/?contractId=contract_123&accessToken=eyJhbGciOiJIUzI1NiIs...&flow=onboarding&locale=es&country=CO&redirectUrl=https%3A%2F%2Fmyapp.com%2Fthank-you
```

## Notes

- `userId` is optional in `onboarding`. If not provided, the backend generates a UUID. Pass your own if you need to match the transaction to your user.
- `userId` is required in `reverification` for matching.
- `nationalIdType` is a subtype of `national-id` specific to each country (e.g., `CC`, `CE`, `TI`, `PPT` in Colombia).
- `redirectUrl` is the page the person's browser opens. It is not a JavaScript callback and does not carry the result.
- `webhookUrl` is optional and temporary. Prefer the webhook configured on the backend.
- This page does not emit `become-kyc:ready`, `become-kyc:event`, `become-kyc:error`, `become-kyc:warning`, or `become:*` events to your application. Listening on your own page, or on a page that only frames this URL, does not receive them.
- You can show the hosted URL in an iframe. The surrounding page still does not receive those events.
- This is separate from the scripts you add to your own application. People open a link. They do not install a package.

## Relationship to Web Components

| Aspect | Web Integration | Web Components |
|--------|-----------------|----------------|
| Deployment | Hosted full-page app | Script you add to your page |
| How it is used | Open a hosted link | Add `<become-kyc-sdk>` to your page |
| Mode | Always `fullscreen` | `embed`, `overlay`, `fullscreen` |
| Configuration | Query parameters and the contract configuration | Attributes, the contract configuration, and `setConfig()` |
| In the browser | `redirectUrl` only | DOM events on `<become-kyc-sdk>`, and `redirect-url`. See [events.md](events.md) |
| Results | Webhook notification, then result retrieval with the API | Webhook notification, then result retrieval with the API |
| Use Case | WhatsApp, email, direct links | Embedded in your application |

Both options run the same verification flow. Embed it in your application with the web component. Use this hosted page when you need to send a link and do not want to host the page yourself. A link to a page of your own that embeds the web component works for WhatsApp and email too. See [Example: WhatsApp flow](integration-guide.md#example-whatsapp-flow).
